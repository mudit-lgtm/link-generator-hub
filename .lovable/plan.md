## Goal

Ship a verifiable QA layer over the existing 35 tools (smoke tests, JSON-LD validator, status dashboard), fix the mega menu on every breakpoint, and add Tier 3 + Tier 4 tools end-to-end (route, sitemap, nav, home).

## 1. Automated smoke tests (per-tool render + form behavior)

`tests/smoke.test.tsx` (new) — runs through every path in `ALL_PATHS`:

- Mount the route component via `@testing-library/react` inside a memory router with a mock `Helmet`/head.
- Assert the `<h1>` text contains the route's primary keyword.
- Assert the right input is present based on tool category:
  - **File uploaders** (`audio`, `video`, `image`, `pdf`, `direct-download`) → `input[type="file"]` with the expected `accept`.
  - **Composers** (`whatsapp`, `mailto`, `calendar`, `utm`, etc.) → at least the documented field count.
  - **Transformers** (`drive`, `dropbox`, `onedrive`, `mega`, `short`, `qr`) → URL input.
- For composers/transformers: fire `userEvent.type(...)` on each field and `click(Generate)`, then assert the output `<code>`/`<pre>` updates and contains the expected token (e.g. `wa.me/` for WhatsApp, `mailto:` for mailto, `magnet:?xt=urn:btih:` for magnet).
- For file uploaders: drop a synthetic `File` and assert `URL.createObjectURL` is called (mocked) and preview node appears.

A small `tests/_fixtures.ts` map declares the per-tool expectations (category + sample input + expected token).

## 2. JSON-LD validation step

`scripts/validate-jsonld.ts` (new) — runs in CI / `bun run qa`:

- Walks `src/routes/*-link-generator.tsx` + `slug-generator.tsx`.
- For each route: spins up the route's `buildHead({...})` call by importing it via Vite SSR (or by statically evaluating the args), then asserts the produced `script` array contains entries with `@type` of:
  - `BreadcrumbList` with `itemListElement[].item` matching `https://link-wizardry-lab.lovable.app<route>`
  - `FAQPage` with at least 3 `mainEntity`
  - `SoftwareApplication` with `name` matching the page name
  - `HowTo` with ≥3 `step`s
- Fails with a clear per-route diff. Wire into `tests/seo.test.ts` as a single `describe.each(ALL_PATHS)` block so `bunx vitest run` covers it.

## 3. QA status dashboard at `/qa`

`src/routes/qa.tsx` (new, `noindex`):

- Imports `ALL_PATHS` + `SEO`.
- Renders a table: route • category • last-checked (read from `src/lib/qa-status.json`) • status badges for `render`, `schema`, `breadcrumbs`, `cta`, `menu`, `preview`.
- `src/lib/qa-status.json` is generated by `bun run qa` (script combines smoke + jsonld results) so the page reflects real test output.
- Top of page: counts (✅/❌), filter dropdown by category, "Run locally: `bun run qa`" snippet.

## 4. Mega menu — desktop + tablet/mobile

`src/components/ToolLayout.tsx`:

- Desktop: `pt-2` invisible hover bridge between trigger and panel, 180ms close delay timer, panel `fixed left-0 right-0 top-[var(--header-h)]` so it spans the viewport (current `absolute` clips inside the header). Add ESC to close, click-outside to close, focus trap.
- Tablet (≥768 <1024): same panel, but condensed to 2 columns, scrollable if overflowing.
- Mobile (<768): hamburger opens a `Sheet` (shadcn) with accordion groups by category.
- Add a Playwright smoke (`tests/menu.spec.ts` driven by `python` Playwright script under `/tmp/browser/`) that opens `/`, hovers Tools, moves cursor across the panel, and screenshots — verifies the panel stays open.
